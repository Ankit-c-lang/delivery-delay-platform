# Serving-only subset — PLAN.md §11, §13 Phase 8.
#
# MEASURED, not guessed. The list below is what a process needs to load the champion pyfunc and
# score one record, determined by loading it and reading sys.modules (DECISIONS.md D38):
#
#   catboost   the shipped model                      (D35 — CatBoost won once threads were pinned)
#   sklearn    the isotonic calibrator (pulls scipy)
#   joblib     the preprocessing artifact's format
#   pandas     the frame the pyfunc takes and returns
#   mlflow     resolving models:/...@champion and unpickling the pyfunc
#
# Excluded on purpose: optuna, shap, matplotlib, lightgbm, xgboost — and, after the import surgery
# in D38, also **pandera, sqlalchemy and psycopg2**. Those three used to be unavoidable: the pyfunc
# imports src.features.build, which imported src.etl.schema for a frozenset of ten column names and
# src.db for an engine it never used at serving. Moving the denylist into the dependency-free
# src/contract.py and making the Postgres imports function-local removed all three. A validation
# framework and a database driver in a serving image are not a rounding error.
#
# pyyaml is NOT listed: mlflow needs it to read MLmodel files and brings it transitively. Listing
# only direct needs keeps this file honest about what the API itself requires.
#
# pyarrow IS listed, and the container is what proved it necessary. The closure measurement showed
# it imported, but it was already present in the dev venv as a dependency of **full** mlflow —
# `pip show pyarrow` reports `Required-by: mlflow` — and `mlflow-skinny` drops it. pandas 3 does not
# require it either (`Requires: numpy, python-dateutil`) despite using PyArrow-backed strings. So
# the first container start failed with `ModuleNotFoundError: No module named 'pyarrow'`.
#
# The lesson is that a venv cannot tell you what an image needs: it only shows what is *present*,
# and everything is present. Only a from-scratch install distinguishes a direct dependency from one
# that happened to be dragged in by something you are about to remove.
#
# mlflow-skinny, not mlflow: the API loads a registered pyfunc and resolves an alias, it never runs
# a tracking server or the UI. Skinny drops those dependencies.
#
# OPERATIONAL COUPLING, worth saying out loud: this file tracks what the CHAMPION ships. If the
# Phase 9 gate promotes a challenger that ships a different library, the image must be rebuilt
# before that promotion can be served. Promotion is therefore not purely a registry operation, and
# Phase 9 should say so rather than imply an alias move is always sufficient.
